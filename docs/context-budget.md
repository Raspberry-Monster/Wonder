# 统一上下文与 Token 预算

所有模型调用使用 `ContextBudget` 创建当前模型的预算，通过 `TokenCounter` 使用已发现的词表或估算器计数。组件之间传递同一个请求的预算对象；不同模型仍各自使用对应词表、窗口和输出设置。它不是跨用户共享的可变余额，也没有新增全局锁。

## 一次请求如何装入上下文

可用输入 = ContextWindow − 输出预留 − 512 Token 余量。计数包含实际格式化后的消息、工具定义、工具调用和结果，以及图片的估算开销。最终发送前，ModelRouter 再检查完整请求。

聊天必须保留系统指令和当前消息。先尝试保留最近一轮对话，再加入摘要、关系、记忆和更早的历史。工具调用期间按优先级移除可选内容：较早历史、记忆、关系、最近历史、摘要；历史按轮整体移除。工具调用及其结果不拆开。必要内容本身超限时明确失败，不截断当前问题。

历史工具按照剩余 Token 筛选记录、缩短摘录。同一轮多个工具结果共用预算，前一个结果会占用后一个结果的空间。必要的工具链增长时，可降低下一次生成的输出上限；仍保留至少配置输出与 256 Token 中的较小值。确实没有空间时返回简短错误或停止，无法保证任意长工具链都能继续。

## 后台任务

### RollingSummary

历史达到 25 条、占用超过输入预算的 55%，或发生历史舍弃时可触发摘要。摘要从前一份摘要之后按顺序读取，数据库每页 80 条是读取批量，不是总处理上限。通常保留最新 6 轮原文；少于 6 轮的长对话至少保留触发任务的当前轮。

每次用完整 Prompt 检查预算；一条长消息也能按字符偏移分片，保留来源和时间。成功后把草稿、游标和来源指纹写入 `Outbox.ProgressJson`，重新排队继续。完整一轮处理完才推进公开摘要的边界；重启后从检查点继续。来源撤回、修改或设置变化会使旧草稿失效。

模型输出截断时最多缩小输入重试两次；生成的摘要超过 600 字符或目标 Token 数时再压缩一次。指令、旧摘要与必要元数据本身已超限，或压缩仍失败时，任务会明确失败，保留可诊断的错误。

### Reflection / Emotion / Relationship / Memory

FullReflection 从最早未处理消息开始读取，每页 100 条，持续推进到任务边界。长消息分片；LightReflection 与 StrongReflection 分别使用自己的模型预算。较小的 Strong 模型会再次拆分待复核片段。

分批结果和来源记录在任务检查点中。所有批次完成后才写入一份 ReflectionResult，创建 Emotion、Relationship、Memory 三类后续任务，避免每处理一个片段就重复触发情绪更新。情绪提案按批次合并，事实和关系提案合并证据来源；分片分析不等价于模型一次看到无限完整对话。

### 记忆维护

优先一次判断候选与相关事实；装不下时，按相关事实及其完整证据分组判断，保存中间决策。分组结束后才提交修改。缺失证据、单组必要证据超限或多组决策无法一致合并时，候选标为 Deferred，已有事实保留。

### Narrative 与其他生成

都经过 ModelRouter 的统一最终预算检查与输出截断检查。固定输入任务不会绕过限制，也不会把 `finish_reason=length` 的不完整输出当作成功结果保存。分批不是对任意 Prompt 自动裁剪：只有理解业务边界的摘要、Reflection 和记忆维护流程负责拆分。

### Embedding

Embedding 的 ContextWindow 表示单次输入上限，无输出预留，同样扣除 512 Token 余量。超长检索问题分块嵌入、分别检索后融合排名。需要持久化的单条事实过长时拒绝或暂缓，避免截断事实却仍将其当作完整证据。

## 配额、失败和诊断

上下文限制、输出截断、日/月配额、传输失败分别处理。后台任务耗尽配额时排到下一 UTC 配额周期，保存已有进度，不消耗失败重试次数；聊天返回额度提示。单次请求本身超过总配额则无法靠等待解决。

控制台模型列表显示实际使用的词表，用量列表显示估算请求数。日志记录任务、模型、词表、输入、输出预留和剩余预算，不记录 Prompt 正文。供应商返回 usage 时采用其数值；未返回时估算。请求发出后结果丢失等不确定失败按预留上限估算结算，可能高于实际费用，不能视为供应商账单。

未匹配词表时仍使用估算；图片与协议开销也存在估算。512 Token 余量不能代替正确配置模型窗口，供应商的实际计数仍可能不同。

## 升级

新增迁移 `20261023034400_ContextBudgetProgress`，仅增加 `Outbox.ProgressJson` 和 `Usage.Estimated` 两列。旧记录无需重写，旧任务可以从头执行。历史 Usage 的默认 false 表示没有新版本估算标记，不证明旧记录都是供应商精确计量。

停止旧 Host，在仓库根目录运行：

```powershell
dotnet run --project src/Wonder.Host -- --migrate
```

然后启动新版本。部署环境使用对应发布包的 `--migrate` 入口。开发验证使用独立临时 PostgreSQL 数据库，没有替用户迁移正在使用的数据库。
