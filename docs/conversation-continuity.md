# 跨 Session 对话延续、当前时间与历史查询

同一个群或同一个人的私聊拥有持续的 Conversation。Session 用于空闲超时、反思和任务分段；结束 Session 后，这段对话的有效近期上下文仍可延续。

## 自动衔接

每次聊天从同一 Bot、同一 Conversation 读取最新有效摘要，再按顺序读取摘要之后的最近 40 条有效消息，按模型上下文预算选择输入。来源可以跨多个 Session，也包括已授权保存但没有触发回复的普通群消息。旧会话只有几条消息、尚未生成摘要时，也可以直接接上近期原文。

滚动摘要在对话范围内延续前一份摘要，保存作者、具体时间、待续话题与来源。它不是逐字历史；需要核实早先细节时可调用历史查询工具。系统要求自然衔接，尊重用户换话题，不编造两个 Session 之间发生过的事情。

## 模型输入中的结构化文本

摘要、Reflection、记忆维护、引用、称呼和工具结果中的结构化内容使用 `Json.ForPrompt` 输出中文，避免将中文先变成 `\uXXXX` 再作为消息正文发送。换行、引号和反斜杠仍按 JSON 规则转义。这里处理的是模型实际读取的消息正文；HTTP 外层 JSON 的传输转义会由供应商解析，不等同于模型正文里的字面转义。

JSON 字段由 `Json.Read` 解析后，使用模型输入格式重新序列化；关系偏好也遵循这一过程。普通聊天、摘要和记忆的 Text 字段作为原文读取。存储使用 `Json.Write`，与模型输入的可读格式分开，保证候选内容哈希和去重依据稳定。

不要对数据库全文执行 `Replace` 或 `Regex.Unescape`：用户可能真的写下了 `\u4F60`、文件路径或带反斜杠的代码。若 Text 字段里实际存的是整段转义文本，需要先确认具体记录的写入来源，再按已知格式修复；它与 JSON 字段中的正常转义不同。Text 原文按用户实际输入保留。

关闭并重新启动 Host 后，只要使用同一个数据库、记录仍有效，就能恢复。停机期间未收到的 QQ 消息仍不会自动补拉，已过保留期或被删除的原文也无法恢复。

## 当前时间

每轮请求都会从系统时钟重新读取当前时间，提供本地时间、UTC、星期、当前消息时间、最近消息时间及间隔；不依赖模型推测日期。默认时区为 Asia/Shanghai，可通过应用配置 Chat:TimeZone 或环境变量 Chat__TimeZone 设置，例如 UTC。

历史消息携带自己的时间。新收到的用户消息使用 OneBot 事件时间；旧记录沿用已有 CreatedAt，不猜测缺失时间。模型被要求将“昨天 / 明天”等相对日期锚定到原消息时间，避免几天后继续聊天时改变原来的约定。

## 两个只读工具

Owner 在“模型路由 → 单独调整任务 → 聊天回复”勾选“启用只读工具”，保存后生效。仅在供应商 / 模型支持兼容 function calling 时开启；默认关闭。批量模型更新不覆盖这项设置。时间注入和自动衔接近期对话始终可用，无需开启工具。

- get_current_time：读取调用瞬间的时间，可指定 time_zone，例如 Asia/Shanghai 或 UTC。
- search_conversation_history：用短关键词 query 查询当前群 / 当前私聊保存的原始消息，可用 after / before 的带时区 ISO 时间筛选，也可用返回的 nextBeforeSequence 翻页。query 为空时列出近期记录。每次最多返回 5 条，每条最多 400 字符，摘录尽量围绕命中关键词，并明确标注截断状态、作者、时间及 Session 标签。结果还会按剩余上下文缩短条数或摘录长度，返回游标可继续翻页。

查询范围由服务端根据本次真实对话决定，模型不能指定另一个 Bot、群或私聊，也不能读取当前请求之后的消息。跨群共享记忆遵循 [显式授权规则](shared-context.md)，私聊不读取共享空间记忆。

工具结果作为不可信历史资料返回。搜索没有匹配结果时，明确告知模型不能编造；模型仍可能不遵循要求，实际效果需要供应商联调。工具最多执行 3 轮、合计 8 次，随后要求模型直接回答；每次生成记录用量，不向 QQ 发送工具中间结果或思考内容。

聊天和 Embedding 协议由 Microsoft.Extensions.AI.OpenAI 官方适配器处理，工具循环使用 FunctionInvokingChatClient，工具 Schema 使用 AIFunctionFactory。仅执行结构化 FunctionCallContent；若供应商把 DSML 调用标签放入普通 content，则拒绝该响应并沿用后台任务重试。发送阶段也检查这类内容，阻止内部标签进入 QQ，并将对应助手历史标为失效。

兼容层按 [DeepSeek 工具与思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/) 保留本轮工具链要求的 reasoning_content，并在后续子请求中回传。旧助手回答作为历史参考输入；临时思考过程不存入聊天正文，也不发到 QQ。

## 隐私与撤回

读取前过滤过期、已失效和来源损坏的记录。助手回答、摘要和历史工具结果会传递原始消息、作者和共享记忆来源。更正 / 删除记忆后，后续 Session 中依赖原作者或原始记录的派生上下文也会停用，并取消关联的待发送回复；保留跨 Session 派生回答的原文供诊断。原有本人派生数据清理规则继续执行。
